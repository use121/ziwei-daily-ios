## 0. 结论先说

1. **两个参考链接是同一个项目**：ouranic.cn 是 Renhuai123/ziwei-doushu 的线上商业站。仓库开源了排盘引擎（MIT）、古籍原文（公版）、两套数据集（CC BY 4.0），**闭源了断语库、AI prompt、后端 API、会员系统**。
2. **能借鉴的是「怎么算」和「怎么组织界面」，不能直接拿的是「怎么说」**。我们 App 的解读文案必须自己写规则生成，这也正好符合现有 `FortuneEngine` 的确定性设计。
3. **我们的排盘内核已经正确但偏薄**：28 颗星（14 主 + 14 辅），没有亮度、神煞、格局、命主身主、流月流时。这些是「看起来专业」与「真的专业」的分水岭。
4. **最大体验缺口是时间维度**：现在只能在今日页看到当前大限/流年的文字摘要，命盘页是静态本命盘。参考站的「本命→大限→流年」一键切换 + 宫位点选联动，是最值得先补的交互。

## 1. 参考实现评估

### 1.1 排盘算法

它的 `algorithm.ts`（641 行）**并不是从零实现**，而是对 `iztro`（TypeScript 紫微斗数库）的封装 + 口径修正补丁：

| 环节 | 它的做法 | 对我们的意义 |
| --- | --- | --- |
| 命宫/身宫 | 委托 iztro | 我们已自实现，无需改 |
| 五行局 | 委托 iztro，只解析「水二局」这类字符串 | 我们已自实现 |
| 紫微定位 | 委托 iztro | 我们已自实现（补数整除 + 单双顺逆） |
| 十四主星 | 委托 iztro | 我们已自实现 |
| 大限顺逆 | 委托 iztro 的 `decadal.range` | 我们已自实现 |
| 亮度 | **自己覆写**，7 档 + 5 个流派可切 | ⭐ 值得移植（查表） |
| 四化 | 自己的 `sihua.ts` 十干四化表 | ⭐ 可核对我们的表 |
| 神煞 | 自己的 `shier-shen.ts` | ⭐ 值得移植（查表） |
| 格局 | 自己的 `patterns.ts`，1100+ 行规则 | ⭐ 精选移植 |
| 真太阳时 | 经度差 + 均时差 | 我们已有 |
| 夏令时 | 1986–1991 区间判定（只判定不自动改） | ⭐ 待补 |
| 闰月 | 四种口径可配（前月/后月/按日切/本月） | ⭐ 待补 |
| 晚子时 | 23:00–23:59 归次日；填了出生地按真太阳时判断 | 我们有开关，但未与真太阳时联动 |

**净结论**：能借鉴的是**口径细节与查表数据**，不是算法框架。我们用 Swift 重写规则即可，不存在代码移植障碍。

### 1.2 许可证边界（重要）

| 内容 | 协议 | 我们能否用 |
| --- | --- | --- |
| 引擎代码（`lib/ziwei/`） | MIT | ✅ 可参考重写，保留声明 |
| 古籍原文（骨髓赋/全书/全集） | 公有领域 | ✅ 可收录 |
| 数据集 v3/v4 | CC BY 4.0 | ⚠️ 技术上可用，但解压 56.6 GB，不适合装进 App；需署名 |
| 倪海厦《天纪》原话 1848 条 | CC BY-NC-SA 4.0 | ❌ **禁商用**，不引入 |
| 断语库（13 主题上万行） | 闭源 | ❌ 拿不到，必须自写 |
| AI prompt / 后端 API / 会员系统 | 闭源 | ❌ 拿不到 |

> 这条边界决定了：我们做的是「同等级的功能」，不是「同文案的复制」。解读质量靠我们自己的规则库深度。

### 1.3 界面与交互（ouranic.cn）

- **布局**：左侧命盘方格 + 时间层切换，右侧解读面板（可拖拽分栏、可放大阅读）；移动端上下堆叠。
- **时间层**：本命 / 大限 / 流年 / 小限 / 流月 / 流日 / 流时，顶部 Tab + 年份 `‹ ›` 步进，切换后盘面叠加该层四化并在 Tab 下方列出「X 年四化：A化禄 B化权…」。
- **宫位点选**：点击宫位 → 三方四正高亮 → 右侧自动注入该宫解读（宫位定性 / 主星解读 / 三方四正联动 / 实际建议）。
- **四化点选**：点某颗星的化禄/权/科/忌 → 自动分析「化X落某宫」的飞化影响。
- **解读结构**：六个主题 Tab（命格/感情/事业/财运/健康/性格）+ 折叠推演层（命盘推演、三方四正联动、四化路径分析、年干四化、命盘依据、经典出处、风险提醒、双星同宫、主辅煞组合、天纪溯源、身宫）。
- **可视化**：命格总览顶部六维雷达图（明确标注「不是人生评分」）。
- **格局卡**：古书格局入口，列出识别到的格局 + 涉及星曜宫位 + 出处。

## 4. 需要你确认的三件事

1. **第一批范围**：按阶段 1 的 P0 全做？还是先只做交互（U1–U4）+ 亮度，解读留到第二批？
2. **Pro 怎么落地**：App 是自签分发，没有 App Store 内购通道。建议做「设置页本地 Pro 开关」——默认解锁全部，Pro 标记仅用于区分内容层级；或者你希望做成需要解锁码激活？
3. **合盘 / AI 问盘要不要**：这两个工作量最大、也最依赖外部条件（合盘是纯本地但翻倍；AI 需要 API Key）。
